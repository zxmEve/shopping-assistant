# ADR-0004：Agent 要少问、先问重要问题，并且知道什么时候停止

> 2026-10-15 更新：单问题／最多三问策略已由[集中追问与字段解决状态方案](../19-agent-expansion-plan.md)替代。下文保留原设计历史；当前问题集合、明确无要求和标准授权规则以新方案及 ADR-0017 为准。

- 状态：已采用
- 日期：2026-09-04
- 关联需求：REQ-02、REQ-03、REQ-04、REQ-05

## 先说结论

Agent 不会一次抛出长问卷，也不会无限追问。系统先判断哪些缺失信息会真正改变商品范围、金额或审批结果，优先询问这些字段；每轮最多三个问题，最多追问三轮。三轮后仍缺少不能安全猜测的信息，就明确停止任务。

## 一个具体例子

用户只说：“帮研发团队采购一批电脑。”

系统可能缺少：

- 单台预算；
- 数量；
- 最低内存；
- 交付城市；
- 预算是否含税。

这五个字段都重要，但影响程度和紧急程度不同。没有预算和数量，系统甚至无法判断采购规模；没有最低内存，可能搜到不能运行开发环境的低配电脑；交付城市和税口径则影响最终成本和审批。

如果一次问五个问题，交互会像填表；如果每轮只问一个，用户可能要来回五次；如果完全让模型自由发挥，它可能重复提问、漏掉预算，或者一直不停止。

## 我们想达到什么效果

1. 只问会影响执行结果的问题。
2. 更重要的问题先问。
3. 尽量减少往返轮数，但不一次输出长问卷。
4. 用户授权使用公司标准时，只使用真实存在的制度默认值。
5. 数量、预算、税口径和交付地等事实不能被擅自猜测。
6. 系统一定会停止，不出现无限澄清循环。

## 比较过的做法

| 做法 | 好处 | 问题 |
|---|---|---|
| 按字段列表固定顺序询问 | 实现最简单 | 可能先问低价值问题，无法解释顺序 |
| 每轮固定问一个 | 对话自然 | 缺失字段多时往返过长 |
| 一次询问所有缺失字段 | 完成轮数最少 | 用户体验接近表单，容易放弃或漏答 |
| 完全由 LLM 决定 | 语言自然，适应性强 | 容易重复、漏问、一次问太多或无法停止 |
| 确定性策略控制字段、数量和停止，LLM 负责理解与表达 | 行为稳定且仍可自然对话 | 需要维护优先级和默认值规则 |

## 最终选择及原因

### 1. 明确进入寻源前必须具备哪些字段

当前 P0 要求数量、单台预算、税口径、交付城市和最低内存。最低存储可在明确的开发机语境下依据公司标准补充，并记录为假设。

为什么：是否可以开始搜索不能只看模型说“信息差不多了”，而应有可测试的业务条件。

### 2. 给缺失字段设置业务优先级

当前顺序大致是：预算、数量、最低内存、交付城市、税口径。

为什么：预算和数量首先决定候选范围与总采购金额；最低配置决定商品是否可用；地点和税口径影响到手成本。先问高影响问题，可以更早排除错误方向。

这里的优先级是当前领域规则，不是假装由数据训练得到的最优模型。

### 3. 根据剩余字段和剩余轮次决定本轮问几个

系统不是简单取前三个字段，而是估算：如果只剩三轮，要在不超过三问的前提下，用尽量少的问题完成澄清。

为什么：这在“每轮一个”和“一次全问”之间取得平衡。缺失字段少时只问一个；缺失很多时才在同一轮组合两到三个。

### 4. 每轮最多三个问题

为什么：三个是当前 P0 的可用性边界，能避免长问卷，同时允许在三轮内收集五个核心字段。这个数字后续应通过用户测试和“不必要问题率”校准。

### 5. 最多追问三轮

三轮后如果仍缺预算、数量、税口径或地点，任务进入明确失败状态并说明缺失内容。

为什么：任务型 Agent 的目标是安全完成工作，不是无限延长对话。明确终止也能防止模型循环和成本失控。

### 6. “按公司标准”只授权使用有制度依据的默认值

目前只有最低内存和最低存储存在公司开发机基线，可以在用户明确授权后填入。每个默认值都写入 `assumptions`，在结果中可见。

为什么：“按公司标准”不是允许系统随便猜。数量、预算、税口径和交付地没有安全默认值，仍必须由用户提供。

### 7. LLM 可以帮助理解，但不能改变停止条件

后续真实模型可以识别用户回答、生成自然问题或提出问题候选；最终的必需字段、单轮数量和最大轮次仍由确定性策略控制。

为什么：自然语言需要语义能力，但任务能否继续和何时停止必须稳定、可测试。

## 实际调用过程

```text
接收用户消息
  -> 抽取或更新需求字段
  -> 保留之前已经确认的字段
  -> 检查用户是否明确授权使用公司标准
  -> 找出仍缺少的必需字段
  -> 按业务影响排序
  -> 根据剩余轮次选择本轮 1～3 个问题
  -> 信息齐全：开始寻源
  -> 达到三轮仍不齐全：停止并说明原因
```

## 这项决策带来的代价

- 当前优先级需要人工维护；
- 不同品类可能需要不同的必需字段和顺序；
- 规则过于保守时可能多问，过于激进时可能过早开始搜索；
- 当前中文规则抽取能力有限，复杂回答后续仍需要 LLM 辅助。

## 测试如何证明它有效

- 空泛需求首先询问预算和数量，而不是随机字段；
- 只缺一个字段时只问一个问题；
- 任何一轮都不会超过三个问题；
- 多轮补充只更新新字段，不丢失已确认信息；
- 用户明确说按公司标准后，内存默认值被填写并留下可见假设；
- 用户连续三轮仍不提供关键信息时，系统进入失败状态并停止继续追问；
- 完整需求不会被重复询问，直接进入寻源。

## 当前限制

- 字段优先级来自领域判断，尚未用大规模标注集计算真正的信息增益；
- 当前评测能证明顺序、数量和停止行为，但还没有完整统计必要问题召回率与不必要问题率；
- 只覆盖笔记本采购，其他品类需要独立 schema 和问题策略。

## 术语对照

- 主动追问：Agent 发现关键事实缺失后主动向用户提问。
- 信息价值：某个答案对缩小候选、确定金额或改变审批路径的影响程度。
- Assumption：系统使用的明确假设，必须让用户看见来源和内容。
- 轮次预算：最多允许进行多少轮澄清，防止无限对话。
