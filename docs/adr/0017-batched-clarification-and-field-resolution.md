# ADR-0017 集中追问与字段解决状态

- 状态：已采用
- 日期：2026-10-15
- 替代：ADR-0004 的单轮问题数量策略及需求 Agent v1 的 Top-1 规则
- 范围：本轮仅契约基础、集中追问及其必要的寻源兼容

## 决策

RequirementSpec v2 使用 ClarificationPlan 保存当前全部阻塞问题，允许按相关字段分组。未知或不支持品类时先问品类。模型输出通过字段覆盖、已回答项、重复、冲突引用和主题检查后保留；遗漏或不合格部分由模板补齐。自由文本的校验是结构与关键词门禁，不代表已经证明任意措辞的语义正确性。

保留 next_question 作为第一个问题的兼容视图。旧快照缺少新字段时自动迁移，不修改既有连续状态历史。字段状态表使用封闭注册字段，保持 OpenAI Agents SDK 原生严格输出 schema 兼容；JSON 中预算字段仍使用带点的字段路径。

配置明确无要求与未回答不同。NO_PREFERENCE 仅允许内存、存储，并必须引用真实用户声明；它不会生成数值。数量、预算、税口径和交付地不能借此跳过。用户授权标准产生 AUTHORIZED_DEFAULT，数字由服务端配置填写，保留授权证据及独立标准来源。当前 1TB 是服务端开发机默认配置，不应描述为制度强制存储下限。

离线、fixture、模型失败 fallback 和 legacy 路径共享需求服务。不再根据「开发」一词静默填充存储。配置无要求时，目录过滤允许空值；既有企业内存底线在目录截断前应用，最终仍执行企业制度校验。工具与 Engine 继续拒绝没有数值且没有无要求证据状态的配置。

追问上限仍为三轮。字段齐全则无问题进入寻源；连续三轮未解决则安全停止。前端展示已记录信息与问题清单，支持一次回答或部分回答。推荐后的输入、未来补查工具和协商状态边保持关闭。

## 验证与限制

覆盖问题保留与局部修复、重复与无关问题、硬软约束、冲突解决、明确无要求、授权标准续轮、旧 JSON 快照、SQL 数据与 SQLite checkpoint 重建，以及创建草稿回归。新增未来事实契约区分未知／不可用与已知值，制度约束不能声明可协商。

真实模型语言质量尚未通过付费 live 评测；离线 SDK schema 校验只证明结构兼容。当前目录只支持笔记本。未来阶段的被动契约不表示相应业务功能已经完成。
