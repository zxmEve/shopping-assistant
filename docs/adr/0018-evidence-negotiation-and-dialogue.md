# ADR 0018：按需事实查询、约束协商与推荐后对话

日期：2026-10-16。状态：已实施。

## 决策

继续保留 Requirement Agent 和 Sourcing Agent 两个角色。消息先经过采购归属路由；同一采购进入对话意图分类，明确区分解释、比较、偏好调整、硬需求变化、候选选择和接受协商。真实模型使用原角色模型执行独立阶段；离线 fixture 使用可重复规则。模型没有状态写入、制度批准或草稿创建权限。

Sourcing 的只读工具扩展为 search_catalog、query_inventory、estimate_delivery、query_warranty。查询参数只接受当前 Run 已召回的 provider/offer_id，数量和地点由服务端绑定。Gateway 负责权限、调用预算、限时、重试、计费、执行日志和幂等；数据适配器目前是本地模拟供应商接口，尚未接真实供应商。

库存和企业制度要求的保修是必需证据；交期在存在硬期限、软交期诉求或交付优先排序时成为必需证据。模型决定查询顺序与候选；确定性证据服务补足最终候选的必要事实。一次最多补查六个候选，兼顾模型提议、最低成本、最快交付及效用范围。目录额外保留至多六个近似报价；事实不足和有限召回不能表述为全市场没有商品。

事实保存状态、来源、数量／地点等适用范围与五分钟有效期。有效缓存按依赖复用；需求变化导致范围改变时重新查询。成功工具日志也必须检查 TTL；过期结果建立新执行。确认前强制读取选中候选的全部必需事实，确认尝试编号区分刷新与中断恢复。

无候选时逐项记录 PASS/FAIL/UNKNOWN、要求值、实际值、来源及调整权限。只有已知事实下存在可行报价时，服务端才提出最多三个约束方案。允许调整单台预算、硬交期、用户内存／存储下限；不调整企业底线、库存数量、供应商准入、成色等约束。上下限复杂区间不自动协商。Sourcing 只能对现有方案 ID 排序；未知事实进入 FACTS_UNAVAILABLE，不能伪造可行方案。

方案绑定需求版本和事实有效期。用户明确接受后，在原始消息上记录结构化同意及 negotiation:// 来源，应用经过验证的变更并重新寻源。不能把用户未说过的数值拼成原文证据。后续普通更新保留此类已验证历史证据。协商轮次独立限制为三轮。

解释与比较保留需求、推荐和正常确认令牌。Sourcing 选择证据焦点，服务端输出精确规格、成本、库存、交期和保修；不直接展示模型自由生成的供应商事实。排序偏好变化基于保留的合规候选重查必要事实、更新评分，并按相同效用基线检查模型排序；硬条件变化重新寻源。候选编号绑定本轮推荐版本，模糊指代定向澄清。

令牌绑定 Run、租户、用户、需求版本、推荐版本、候选、报价及必要事实摘要。无效令牌在消费 LangGraph interrupt 前拒绝，避免污染后续合法确认。任何未满足／未知／过期必需事实阻止写入；满足条件但事实发生变化，仍需用户重新确认。写入边界再次检查候选和事实时效。重复确认返回原草稿；已授权但中断的确认从 checkpoint 恢复。

## 后果与限制

- 增加查询调用量，以候选上限和 Harness 多层预算约束。新任务执行计数额度更新，费用、token、并发和平台／租户费用上限不放宽。
- 老快照默认空字段兼容；既有任务保存的预算不自动放大。旧推荐缺少事实时必须先刷新并再次确认。
- 当前只支持笔记本、有限目录召回及本地供应商模拟。未承诺真实库存、全球保修或真实交期。
- 偏好重排复用当前合规候选池；硬条件变化重新召回。未实现全量商品索引、真实支付、真实下单或多品类采购。
- 当前解释使用服务端事实渲染，模型措辞、召回覆盖率与工具选择质量仍需付费真实模型评测。
