# 需求校验副作用：根因、修复和同输出回归

结论：针对真实模型留出集中10条被校验改差的用例，修复了背景数量选择、容量/保修证据核验、预算撤销以及旧约束回填。固定同一批24份模型提议重放后，最终遗漏10→0、无依据新增2→0、排除已知表示差异后的其他错误4→0；严格整条通过4/24→8/24。其余16条仍因城市别名或系统大小写未满足规范值契约而失败，本次没有修改标签、评分器或Prompt来提高分数。

## 为什么使用同一批模型输出

本轮目标是定位后端副作用，重新采样模型会混入输出波动。因此新增`requirement_replay.py`，读取上轮真实报告的`proposal_spec`、输入消息与完整基础快照，执行与业务链路相同的“validate → 抛错时propose → validate”流程，再用原评分器评分。

先使用修复前源码快照重放，24条的最终评分与语义事实全部复现；再使用当前代码重放。每条proposal与原始分数、输入指纹保持一致。数据集、评分器及原始live报告均以哈希校验，任意变化会拒绝比较。

本轮新增模型请求0、token 0，是后端验证层回归，不是重新测量模型效果。原始真实调用的输入112,667、输出29,037 token及模型耗时保留为来源测量；重放报告不会把这些历史消耗冒充本轮消耗。后端重放耗时单独记录，不把单次本地小样本当性能结论。

## 三条主要问题如何发生与修复

### 背景数量被当成当前采购数量

原来`_quantity_mention()`只识别少量紧邻数字的更正词；没命中时取第一个“数字+台/件”。“本次只买9台”没有覆盖到，前面已经买完的显示器30台反而被取中。校验因此拒绝模型正确的9台，整份兜底又把品类和数量变成monitor、30台。小王建议40台、本次确认11台的用例同样触发。

现在将当前作用域判断放入`requirement_evidence.py`，在解析与校验中共用：

- 排除明确的历史、库存、已完成事项及建议采购背景，保留原始字符位置供证据核对。
- 明确的当前采购、更正或最终确认优先；多个仍有效且互相冲突的数量不擅自选第一个，转为待确认。
- “原来…保留”是重新确认，不当成过期背景；单独增加回归保护。
- 模型仅引用真实的背景数量也不能据此授权本次采购；继承已有确认数量和当前用户明确的新数量则分别核验。

修复后04、05继续采用模型识别的9台、11台，不再误触发整份兜底。即使模型整体失败，规则解析器也遵循相同的作用域规则。

### 有效条件被删除或被旧值覆盖

原校验只检查数字字符串是否出现在引用里，并特判`1TB=1024GB`。因此`1.5TB→1536GB`、`2TB→2048GB`及“两年半→30个月”会被视为无依据并删除。容量规则还枚举了少数常见值，兜底不能恢复24GB、48GB、768GB等条件。

新规则按字段、数值和单位核验，不再以字符串子串充当数值证据：

- 容量使用Decimal换算，沿用项目冻结的`1TB=1024GB`口径，支持整数和小数TB/GB以及任意正整数GB。
- 区分内存、存储与相邻字段，拒绝把硬盘引用当内存；`GBps`不当容量。上限/下限限定词按对应字段附近的语句识别，不能借用预算上限。
- 唯一、精确的字段容量引用可以由后端规范化数值，例如模型把`0.5TB`填成500GB，后端按契约修正为512GB；证据无法支撑的条件仍不能进入可信需求。
- 保修支持中文数字、小数年及半年，转换为整月；“两年半”保留为30个月。
- 冲突的上下界都保留，再计算冲突，避免删掉2TB下限后把矛盾伪装成已解决。
- 当前明确的新硬下限替换相同维度的旧下限；仅新增软偏好时继续保留旧硬要求。补齐服务不得把旧16GB/1024GB加回48GB/2048GB的新需求。
- 对约束ID增加唯一性检查，将模型的点分隔约束路径规范化到实际约束ID和完整值，避免delta与最终事实不一致。

### 撤销预算后恢复旧值

22号用例中，模型已经清空预算，但用了`REPLACE + null`并引用撤销语句。旧校验要求delta证据同时被某个“仍然存在的字段”使用；被删除的预算没有字段可引用，因此被拒绝。兜底从基础快照复制8000，既不理解“作废/未批准”，补齐服务又将旧金额填回，最终错误地继续使用旧预算。

修复分成两个互相保护的部分：

1. 识别当前、明确且指向预算/单价的撤销或待批准语句。在规则兜底中同样清除maximum/target及旧预算解析状态，重新计算缺失项与追问；后面若有新的明确单件上限，则采用新值。否定、假设、历史事件和他人建议不能触发撤销。
2. 对删除操作单独验证：基础快照中必须存在相符旧金额；新值确为null；引用来自当前用户，字符位置有效，而且引用本身必须能说明预算撤销或明确预算口径变化。满足后将`REPLACE + null`规范化为REMOVE，并允许这类删除证据不再挂在存活字段上。城市引用、错误旧值或悬空引用仍被拒绝。

生产引擎仍保留拒绝不可信模型输出并兜底的流程。新增测试强制让模型版本不合法，经过真实引擎的拒绝/兜底分支后，预算仍为空、状态仍为WAITING_USER，不会恢复旧授权值。
